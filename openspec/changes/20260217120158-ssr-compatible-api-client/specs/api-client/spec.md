# api-request 规范（SSR兼容版本）

## 目的

提供统一的HTTP客户端架构，**同时支持服务端渲染（SSR）和客户端渲染**，基于`ky`和`@tanstack/react-query`，支持类型安全的数据获取、缓存管理和错误处理。

## 修改需求

### 需求：SSR兼容的统一HTTP客户端

系统**必须**提供基于`ky`的统一HTTP客户端封装，**必须**同时支持服务端和客户端使用，**必须**支持请求/响应拦截、统一错误处理和类型安全。

#### 场景：服务端使用API客户端

- **当** 服务端组件需要获取数据时
- **那么** 可以直接调用`get/post/put/delete`函数
- **并且** 可以通过headers参数传入认证token
- **并且** 不依赖`window`或`localStorage`

#### 场景：客户端使用API客户端

- **当** 客户端组件使用API客户端时
- **那么** 自动从`localStorage`获取认证token
- **并且** 支持React Query hooks集成
- **并且** 自动处理请求拦截

#### 场景：创建HTTP客户端实例

- **当** 应用初始化时
- **那么** 创建配置了基础URL、超时、重试策略的ky客户端实例
- **并且** 支持请求/响应拦截器
- **并且** 根据运行环境自动选择token获取方式

#### 场景：处理API错误

- **当** API请求返回非2xx状态码时
- **那么** 自动转换为`ApiError`类型
- **并且** 包含状态码、状态文本和错误数据

#### 场景：网络错误处理

- **当** 发生网络错误时
- **那么** 返回友好的错误消息
- **并且** 错误类型为`ApiError`

## 新增需求

### 需求：服务端数据获取函数

系统**必须**提供可直接在服务端组件中使用的数据获取函数，**必须**支持类型安全。

#### 场景：服务端组件获取数据

- **当** 服务端组件需要获取数据时
- **那么** 可以直接调用`get/post/put/delete`函数
- **并且** 支持传入headers（如认证token）
- **并且** 返回类型安全的响应数据

### 需求：React Query集成（客户端）

系统**必须**提供基于`@tanstack/react-query`的数据获取和缓存能力，**必须**封装为类型安全的hooks，**必须**使用统一的API客户端。

#### 场景：使用API Query Hook

- **当** 客户端组件需要使用`useApiQuery`获取数据时
- **那么** 提供类型安全的查询hook
- **并且** 自动处理加载状态、错误状态和数据缓存
- **并且** 使用统一的API客户端（自动处理token）

#### 场景：使用API Mutation Hook

- **当** 客户端组件需要使用`useApiMutation`进行数据变更时
- **那么** 提供类型安全的变更hook
- **并且** 成功后自动使相关查询失效

### 需求：React Query Provider配置

系统**必须**在应用根布局中集成React Query Provider，**必须**配置默认的查询选项。

#### 场景：初始化QueryClient

- **当** 应用启动时
- **那么** 创建QueryClient实例
- **并且** 配置默认的staleTime、gcTime和重试策略

## 实现约束

1. **单一文件原则**：核心请求逻辑集中在`src/lib/api/request.ts`一个文件中
2. **命名规范**：使用`request`而非`client`，更准确地反映其作为请求工具的本质
3. **环境检测**：使用`typeof window === 'undefined'`判断服务端环境，但不在客户端逻辑中直接使用
4. **Token处理**：
   - 服务端：通过函数参数传入headers
   - 客户端：自动从localStorage获取
5. **类型安全**：所有函数必须提供完整的TypeScript类型定义
