## 新增需求

### 需求：列管理面板（Column Management UI）

系统必须提供一个可视化的列管理界面，允许用户在不修改代码的情况下调整列的显示顺序、宽度、可见性和固定位置。

#### 场景：打开列管理面板
- **当** 用户点击表格表头右侧的"列管理"按钮（或使用快捷键）
- **那么** 必须打开一个 Drawer/Popover 形式的列管理面板
- **并且** 面板中必须列出所有可配置的列，显示列的标题、当前宽度、可见性状态和固定位置

#### 场景：切换列可见性
- **当** 用户在列管理面板中勾选或取消勾选某个列的 checkbox
- **那么** 表格必须立即更新，隐藏或显示对应的列
- **并且** 变更必须实时预览，无需点击"应用"按钮即可看到效果

#### 场景：拖拽调整列顺序
- **当** 用户在列管理面板中拖拽某个列项改变其顺序
- **那么** 表格必须立即更新列的显示顺序
- **并且** 变更必须实时预览，拖拽结束后列顺序立即生效

#### 场景：调整列宽
- **当** 用户在列管理面板中输入新的列宽值（或使用滑块）
- **那么** 表格必须立即更新对应列的宽度
- **并且** 列宽必须受 `minWidth` 和 `maxWidth` 约束，超出范围时自动裁剪

#### 场景：切换列固定位置
- **当** 用户在列管理面板中选择某个列的固定位置（左/右/无）
- **那么** 表格必须立即更新列的固定状态
- **并且** 固定列必须移动到对应的固定区域（左侧或右侧），滚动时保持可见

#### 场景：重置列配置
- **当** 用户点击列管理面板中的"重置"按钮
- **那么** 表格必须恢复为初始列配置（从 `ColumnConfig` 读取）
- **并且** 所有用户自定义的列顺序、宽度、可见性、固定位置必须清除

#### 场景：列配置持久化
- **当** 用户调整列配置后关闭列管理面板
- **那么** 系统必须自动将列配置保存到 `localStorage`（key: `grid-${gridId}-columns`）
- **并且** 下次打开表格时，必须自动恢复上次保存的列配置
- **并且** 如果用户点击"重置"，必须清除持久化的配置

### 需求：列虚拟化（Column Virtualization）

系统必须在列数超过阈值时自动启用列虚拟化，仅渲染可见区域的列，以提升大数据量场景下的滚动性能。

#### 场景：自动启用列虚拟化
- **当** 表格的可见列数超过阈值（默认 30 列，可通过 prop 配置）时
- **那么** 系统必须自动启用列虚拟化
- **并且** 仅渲染当前可见区域的列，不可见列不创建 DOM 节点

#### 场景：列虚拟化滚动
- **当** 用户水平滚动表格时
- **那么** 虚拟化引擎必须计算可见列范围，动态渲染进入视口的列
- **并且** 滚动必须流畅，无明显卡顿或闪烁

#### 场景：列虚拟化与行虚拟化组合
- **当** 表格同时启用行虚拟化和列虚拟化时
- **那么** 系统必须正确渲染可见区域的单元格（行 × 列的交叉区域）
- **并且** 滚动性能必须保持可接受水平（60fps）

### 需求：列固定（Column Pinning）

系统必须支持将列固定到左侧或右侧，滚动时固定列保持可见，提供类似 Excel 的冻结列功能。

#### 场景：固定列到左侧
- **当** 用户将某个列设置为"固定到左侧"时
- **那么** 该列必须移动到表格左侧的固定区域
- **并且** 水平滚动时，固定列必须保持可见，不随内容滚动

#### 场景：固定列到右侧
- **当** 用户将某个列设置为"固定到右侧"时
- **那么** 该列必须移动到表格右侧的固定区域
- **并且** 水平滚动时，固定列必须保持可见，不随内容滚动

#### 场景：固定列与滚动列同步
- **当** 表格包含固定列和滚动列时
- **那么** 固定列的表头高度必须与滚动列的表头高度一致
- **并且** 固定列的行高必须与滚动列的行高一致，视觉上无缝衔接

#### 场景：固定列区域拖拽限制
- **当** 用户在列管理面板中拖拽列时
- **那么** 左固定区的列只能在左固定区内重排
- **并且** 右固定区的列只能在右固定区内重排
- **并且** 中间滚动区的列可以移动到固定区，但需要明确的操作（而非拖拽跨越）

### 需求：列宽自动调整（Auto-Sizing）

系统必须支持通过双击列边缘自动调整列宽，以适应列内容的宽度。

#### 场景：双击列边缘自动调整
- **当** 用户双击列边缘（列分隔线）时
- **那么** 系统必须测量当前可见行中该列的内容宽度
- **并且** 自动设置列宽为 `max(headerWidth, maxCellWidth) + padding`
- **并且** 列宽必须受 `minWidth` 和 `maxWidth` 约束

#### 场景：自动调整的测量范围
- **当** 系统执行列宽自动调整时
- **那么** 必须仅测量当前可见行的内容宽度（而非全量数据）
- **并且** 必须同时考虑表头宽度，确保列宽不小于表头宽度

#### 场景：自动调整的视觉反馈
- **当** 用户将鼠标悬停在列边缘时
- **那么** 必须显示可拖拽的视觉提示（例如光标变为 `col-resize`）
- **并且** 双击后必须立即应用新的列宽，无需额外确认

## 修改需求

### 需求：通用数据表格内核

系统必须提供一个与 UI 框架无关的通用数据表格内核，用于在多个前端项目中复用统一的数据查询协议、列配置模型和插件机制。

#### 场景：定义查询与结果协议
- **当** 任一前端项目需要展示支持排序、过滤、分页与分组的数据表格时
- **那么** 必须能够使用统一的 `DataGridQuery` 结构描述排序、过滤、分页与分组条件
- **并且** 后端返回的数据必须能够映射到统一的 `DataGridResult` 结构，以便多个项目共享相同的数据访问层实现

#### 场景：列配置模型可复用
- **当** 不同项目需要对相同领域实体（例如产品、用户、订单）构建表格列时
- **那么** 必须能够通过统一的 `ColumnConfig` 与 `ColumnMeta` 模型描述列 id、标题、访问器与元数据（类型、可编辑性、权限等）
- **并且** 相同的列配置可以在不同项目中直接复用，而无需依赖具体 UI 组件库
- **并且** `ColumnConfig` 必须支持运行时列状态（顺序、宽度、可见性、固定位置）的扩展，这些状态存储在 `DataGridViewState` 中，而非直接修改 `ColumnConfig`

### 需求：React 表格绑定层

系统必须提供一个基于 React 的表格绑定层，将通用内核与 TanStack React Table、Zustand 状态管理和虚拟化渲染集成在一起。

#### 场景：通过 Hook 获取表格实例
- **当** 前端项目在 React 组件中使用数据表格时
- **那么** 必须能够通过 `useDataGrid` Hook 获取包含表格状态、行数据、列配置与常用交互处理函数的表格实例
- **并且** 该 Hook 内部必须使用通用内核定义的协议与控制器，而不是在业务组件中直接操作 TanStack Table 的底层细节
- **并且** Hook 必须支持列状态（顺序、宽度、可见性、固定位置）的恢复与持久化

#### 场景：支持多表实例与状态隔离
- **当** 页面上存在多个数据表格实例或同一数据表格在多个页面/组件中复用时
- **那么** 每个数据表格实例必须有独立的状态存储（例如每个表一个 Zustand store）
- **并且** 必须能够通过唯一的 `gridId` 在需要时共享或恢复表格视图状态（例如列布局、排序与过滤配置）
- **并且** 列状态（顺序、宽度、可见性、固定位置）必须与 `gridId` 关联，支持独立持久化
