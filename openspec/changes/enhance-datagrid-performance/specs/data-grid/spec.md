## 修改需求

### 需求：多项目复用与性能
系统必须支持在多个项目中复用相同的表格内核与 React 绑定层，并在万行数据规模下保持可接受的性能体验。

#### 场景：多项目依赖同一 @maita-table 包
- **当** 不同前端项目通过包管理工具安装 `@maita-table/*` 依赖时
- **那么** 它们必须能够使用相同版本的查询协议、列模型与 React 表格组件，而无需复制粘贴实现
- **并且** 任一项目中的增强（例如新增列类型或插件）可以在不破坏公共 API 的情况下发布为新版本并被其他项目升级使用

#### 场景：万行数据下流畅滚动
- **当** 表格需要展示万行级数据（可以通过分页或无限滚动方式获取）时
- **那么** React 表格绑定层必须支持基于虚拟化的行渲染，避免一次性渲染全部 DOM 行
- **并且** 对排序、过滤与分页的变更必须通过统一的查询协议推到数据源层处理，而不是在前端对全量数据进行计算

#### 场景：列虚拟化支持
- **当** 表格需要展示 50+ 列数据时
- **那么** React 表格绑定层必须支持基于虚拟化的列渲染，只渲染可见列和 overscan 列
- **并且** 固定列（pinned columns）必须始终可见，不受列虚拟化影响
- **并且** 横向滚动性能必须保持流畅，避免因列数过多导致的性能下降

#### 场景：动态行高计算
- **当** 表格行内容高度不一致时
- **那么** 系统必须使用 `ResizeObserver` 测量实际行高
- **并且** 行高必须缓存到运行时状态中，避免重复测量
- **并且** 虚拟化渲染时必须使用实际行高，而不是固定估算值
- **并且** 行高变化时必须正确更新虚拟化计算

#### 场景：增量数据加载
- **当** 表格需要加载大量数据（> 10,000 行）时
- **那么** 系统必须支持分块加载数据，避免一次性加载导致卡顿
- **并且** 必须显示加载进度（已加载行数/总行数）
- **并且** 加载过程中表格必须保持可交互状态
- **并且** 已加载的数据必须立即可见，无需等待全部数据加载完成

#### 场景：滚动性能优化
- **当** 用户快速滚动表格时
- **那么** 虚拟化的 overscan 必须根据滚动速度动态调整（快速滚动时增加 overscan，慢速时减少）
- **并且** 滚动事件处理必须使用节流（throttle）优化，避免过于频繁的状态更新
- **并且** 必须减少不必要的重渲染，只更新可见区域
