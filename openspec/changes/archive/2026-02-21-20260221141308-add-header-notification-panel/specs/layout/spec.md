# Header 通知功能规范

## 目的

提供 Header 中的静态通知功能，允许用户查看系统通知、消息提醒等信息，提供通知管理能力。

## 新增需求

### 需求：通知图标按钮

系统**必须**在 Header 右侧提供通知图标按钮，**必须**显示未读通知数量徽章，**必须**点击后打开通知面板。

#### 场景：显示通知图标按钮

- **当** Header 组件渲染时
- **那么** 在右侧按钮区域显示通知图标按钮（铃铛图标）
- **并且** 通知按钮位于全屏按钮和用户导航之间
- **并且** 通知按钮使用合适的图标和样式

#### 场景：显示未读数量徽章

- **当** 存在未读通知时（`unreadCount > 0`）
- **那么** 在通知图标上显示未读数量徽章
- **并且** 徽章显示未读通知的数量
- **并且** 徽章使用醒目的颜色（如红色）
- **当** 未读通知数量为 0 时
- **那么** 不显示未读数量徽章

#### 场景：打开通知面板

- **当** 用户点击通知图标按钮时
- **那么** 打开通知面板（Sheet 从右侧滑出）
- **并且** 通知面板显示通知列表
- **并且** 通知面板支持关闭（点击遮罩层或关闭按钮）

### 需求：通知面板

系统**必须**提供通知面板组件，**必须**使用 Sheet 组件实现侧边栏，**必须**显示通知列表和操作按钮。

#### 场景：打开通知面板

- **当** 用户点击通知图标按钮时
- **那么** 通知面板从右侧滑出
- **并且** 显示面板标题"通知"
- **并且** 显示通知列表
- **并且** 显示底部操作按钮（清空、查看所有消息）

#### 场景：关闭通知面板

- **当** 用户点击通知面板的关闭按钮或遮罩层时
- **那么** 关闭通知面板
- **并且** 通知面板从右侧滑出消失

#### 场景：显示通知列表

- **当** 通知面板打开时
- **那么** 显示通知列表
- **并且** 每个通知项包含：
  - 通知头像（支持图片或文字头像，如 "VB"）
  - 通知标题（如 "收到了14份新周报"）
  - 通知描述（如 "描述信息描述信息描述信息"）
  - 时间戳（如 "3小时前"、"刚刚"、"2024-01-01"）
  - 操作按钮（标记已读/删除）
- **并且** 已读和未读通知在视觉上有所区分（如未读显示黑点）

#### 场景：通知列表为空

- **当** 通知列表为空时
- **那么** 显示空状态提示（如 "暂无通知"）
- **并且** 不显示通知列表项

### 需求：通知操作功能

系统**必须**提供通知操作功能，**必须**支持标记已读、删除通知、清空所有通知和查看所有消息。

#### 场景：标记通知为已读

- **当** 用户点击通知项的操作按钮（标记已读）时
- **那么** 将该通知标记为已读
- **并且** 更新通知项的样式（移除未读标识）
- **并且** 更新未读通知数量
- **并且** 如果未读数量为 0，隐藏未读数量徽章

#### 场景：删除通知

- **当** 用户点击通知项的操作按钮（删除）时
- **那么** 从通知列表中删除该通知
- **并且** 更新通知列表显示
- **并且** 如果删除的是未读通知，更新未读通知数量

#### 场景：清空所有通知

- **当** 用户点击"清空"按钮时
- **那么** 清空所有通知
- **并且** 通知列表变为空
- **并且** 未读通知数量变为 0
- **并且** 隐藏未读数量徽章
- **并且** 显示空状态提示

#### 场景：查看所有消息

- **当** 用户点击"查看所有消息"按钮时
- **那么** 跳转到通知页面（如 `/dashboard/notifications`）
- **并且** 如果页面不存在，可以暂时跳转到首页或显示提示

### 需求：通知数据管理

系统**必须**提供通知数据管理机制，**必须**支持静态通知数据，**必须**管理未读通知数量。

#### 场景：加载通知数据

- **当** 应用初始化时
- **那么** 从静态数据源加载通知列表
- **并且** 计算未读通知数量
- **并且** 在通知图标上显示未读数量徽章（如果有未读通知）

#### 场景：更新通知数据

- **当** 用户执行通知操作（标记已读、删除、清空）时
- **那么** 更新通知列表数据
- **并且** 重新计算未读通知数量
- **并且** 更新 UI 显示

### 需求：通知数据结构

系统**必须**定义通知数据结构，**必须**包含必要的通知信息。

#### 数据结构

```typescript
interface Notification {
  id: string; // 唯一标识
  avatar?: string; // 头像图片 URL（可选）
  avatarText?: string; // 头像文字（如 "VB"）（可选）
  title: string; // 通知标题
  description: string; // 通知描述
  timestamp: string; // 时间戳（相对时间如 "3小时前" 或绝对时间如 "2024-01-01"）
  isRead: boolean; // 是否已读
  type?: 'info' | 'warning' | 'success' | 'error'; // 通知类型（可选）
}
```

## 实现约束

1. **UI 组件**：使用 shadcn/ui 的 `Sheet` 组件作为通知面板容器
2. **状态管理**：可以使用 Zustand 管理通知状态，注意 SSR 兼容性
3. **数据源**：使用静态数据，不需要后端 API
4. **国际化**：时间戳格式化需要考虑多语言支持
5. **性能**：如果通知列表很长，考虑虚拟滚动优化
6. **可访问性**：通知面板必须支持键盘导航和屏幕阅读器
7. **类型安全**：所有新增接口和函数必须提供完整的 TypeScript 类型定义

## 修改需求

### 需求：Header 组件扩展

系统**必须**修改 Header 组件，**必须**添加通知图标按钮和通知面板集成。

#### 场景：添加通知按钮

- **当** Header 组件渲染时
- **那么** 在右侧按钮区域添加通知图标按钮
- **并且** 通知按钮位于全屏按钮和用户导航之间
- **并且** 通知按钮使用 `Icons.bell` 图标

#### 场景：集成通知面板

- **当** Header 组件渲染时
- **那么** 引入 `NotificationPanel` 组件
- **并且** 管理通知面板的打开/关闭状态
- **并且** 传递必要的 props 给通知面板

### 需求：图标库扩展

系统**必须**扩展图标库，**必须**添加通知图标。

#### 场景：添加通知图标

- **当** 系统需要显示通知图标时
- **那么** 使用 `Icons.bell` 图标（对应 `IconBell`）
- **并且** 图标正确显示在 Header 右侧按钮区域
