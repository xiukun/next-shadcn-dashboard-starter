## 新增需求

### 需求：个人资料页面基于认证上下文展示模拟用户与组织信息

系统必须提供一个“个人资料/账号信息”视图，用于在 MSW 模式下展示当前登录用户与所属组织的基础信息，并清晰标注其为“模拟数据”，以便未来接入真实后端时可直接复用页面结构：

- 页面只能通过认证上下文（例如 `useAuthContext`）获取当前用户与组织信息。
- 页面展示的头像、姓名、邮箱等必须来源于 `AuthSession.user`，组织名称与角色必须来源于 `AuthSession.organization`。
- 当未登录时，页面应提供友好的提示，而不是直接渲染第三方账户管理组件。

#### 场景：已登录时展示当前模拟用户与组织

- **当** 用户已通过 MSW 模式完成登录
- **当** 用户访问个人资料页面（例如仪表盘中的“个人中心/个人资料”）
- **那么** 页面必须通过认证上下文读取当前用户与组织信息
- **并且** 在卡片中展示：
  - 用户头像（如有）、姓名与邮箱
  - 可读的用户 ID（例如以等宽字体显示）
  - 当前工作空间名称与角色（如存在组织信息）
- **并且** 页面文案中必须明确提示这些信息由 MSW + Faker 模拟生成，仅用于本地开发与 UI 预览

#### 场景：未登录访问个人资料页面

- **当** 当前不存在已登录会话（认证上下文中的 `user === null`）
- **当** 用户直接访问个人资料页面
- **那么** 页面不得尝试渲染第三方账户管理组件
- **并且** 必须以友好的文案提示用户“当前未登录，请先通过登录页完成模拟登录”，或等价的引导信息
