# data-grid 规范增量（Zod-only 结构化验证）

## 修改需求

### 需求：结构化验证支持

系统必须仅通过 Zod Schema 执行结构化验证，不再支持旧的 `meta.validate` 函数或任意返回字符串的自定义校验函数；所有列级与行级校验行为都必须可由 Zod 类型系统精确描述，并产出结构化的错误信息以供 UI 与提交逻辑复用。

#### 场景：列级 Zod Schema 验证（Zod-only）
- **当** 开发者在列配置中提供 `meta.zodSchema` 或通过辅助函数生成列级 Zod Schema 时
- **那么** 表格必须使用该 Zod Schema 作为该列的**唯一**结构化校验来源
- **并且** 如果验证失败，必须返回结构化的错误信息（字段路径 -> 错误消息），而不是仅返回自由格式字符串

#### 场景：行级 Zod Schema 验证
- **当** 开发者通过 `createRowSchema(columns)`（或等价 API）基于列配置生成行级 Zod Schema 时
- **那么** 表格必须能够在提交前对整行数据执行行级校验
- **并且** 必须支持跨列验证（例如：总价 = 单价 × 数量）、必填字段组合约束等复杂规则

#### 场景：不再接受旧的 validate 函数
- **当** 列配置中包含 `meta.validate` 或其它期望返回错误字符串的“旧式校验函数”时
- **那么** 系统不得再依赖该函数执行结构化验证
- **并且** 在开发阶段应通过类型提示或运行时错误向开发者发出明确警告，指引改为使用 Zod Schema
- **并且** 所有新功能与示例必须只展示 Zod 校验用法，不再提供基于 `validate` 的示例或 API 说明
