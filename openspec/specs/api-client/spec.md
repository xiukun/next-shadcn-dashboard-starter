# api-request 规范

## 目的

提供统一的 HTTP 客户端架构，基于 `ky` 和 `@tanstack/react-query`，支持类型安全的数据获取、缓存管理和错误处理。

## 需求

### 需求：统一 HTTP 客户端

系统**必须**提供基于 `ky` 的统一 HTTP 客户端封装，**必须**支持请求/响应拦截、统一错误处理和类型安全。

#### 场景：创建 HTTP 客户端实例

- **当** 应用初始化时
- **那么** 创建配置了基础 URL、超时、重试策略的 ky 客户端实例
- **并且** 支持请求/响应拦截器

#### 场景：处理 API 错误

- **当** API 请求返回非 2xx 状态码时
- **那么** 自动转换为 `ApiError` 类型
- **并且** 包含状态码、状态文本和错误数据

#### 场景：网络错误处理

- **当** 发生网络错误时
- **那么** 返回友好的错误消息
- **并且** 错误类型为 `ApiError`

### 需求：React Query 集成

系统**必须**提供基于 `@tanstack/react-query` 的数据获取和缓存能力，**必须**封装为类型安全的 hooks。

#### 场景：使用 API Query Hook

- **当** 组件需要使用 `useApiQuery` 获取数据时
- **那么** 提供类型安全的查询 hook
- **并且** 自动处理加载状态、错误状态和数据缓存

#### 场景：使用 API Mutation Hook

- **当** 组件需要使用 `useApiMutation` 进行数据变更时
- **那么** 提供类型安全的变更 hook
- **并且** 成功后自动使相关查询失效

#### 场景：查询数据自动解包

- **当** 使用 `useApiQueryData` 时
- **那么** 自动解包 API 响应中的 `data` 字段
- **并且** 返回解包后的数据和状态

### 需求：React Query Provider 配置

系统**必须**在应用根布局中集成 React Query Provider，**必须**配置默认的查询选项。

#### 场景：初始化 QueryClient

- **当** 应用启动时
- **那么** 创建 QueryClient 实例
- **并且** 配置默认的 staleTime、gcTime 和重试策略

#### 场景：开发工具集成

- **当** 在开发环境中运行时
- **那么** 自动启用 React Query Devtools
- **并且** 提供查询和缓存的调试界面

### 需求：Mock 数据支持

系统**必须**支持开发环境下的 mock 数据拦截，**必须**与 `@faker-js/faker` 集成。

#### 场景：Mock 响应生成

- **当** 启用 mock 模式时
- **那么** 使用 faker 生成模拟数据
- **并且** 支持可配置的网络延迟

#### 场景：Mock 开关控制

- **当** 设置环境变量 `NEXT_PUBLIC_USE_MOCK=true` 时
- **那么** 启用 mock 数据拦截
- **并且** 在开发环境中使用模拟 API 响应
