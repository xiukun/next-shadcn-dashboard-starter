## 需求
### 需求：MSW 模式下的模拟登录与会话管理

系统在开发/演示环境中必须支持基于 MSW（Mock Service Worker）的“网络级”模拟认证能力，用于在不依赖 Clerk 云服务或真实后端的情况下完成登录、登出与会话管理，并为未来接入真实认证后端预留统一适配层：

- 登录、登出与获取当前会话须通过 HTTP 接口完成（例如 `/auth/login`、`/auth/logout`、`/auth/me`），由 MSW 在前端拦截并返回约定结构的 JSON 响应。
- 会话对象必须包含访问令牌以及当前用户与组织的基础信息（如：`{ accessToken, user, organization }`），并通过统一的 `auth client` 抽象暴露给前端组件。
- 在 MSW 模式下，前端 UI（登录页、导航、工作区切换、个人资料等）不得再直接依赖 Clerk 组件或 Hook，而是通过 `auth client` / `AuthProvider` 暴露的上下文获取认证信息。

#### 场景：任意非空账号密码登录成功

- **当** 用户在登录页面输入任意非空的账号与密码并提交
- **那么** 系统必须调用 `/auth/login` 接口
- **并且** MSW 必须拦截该请求并返回包含以下字段的 JSON：
  - `accessToken`：非空字符串，用于表示当前会话令牌
  - `user`：包含 `id`、`name`、`email` 和可选的 `avatarUrl`
  - `organization`（可选）：包含 `id`、`name` 和 `role`
- **并且** `auth client` 必须将该响应转换为内部的 `AuthSession` 对象并缓存为“当前会话”
- **并且** 登录成功后，前端必须能够基于该会话跳转到受保护的仪表盘页面（例如 `/dashboard/overview`）

#### 场景：查询当前会话信息

- **当** 浏览器存在已登录的会话（例如当前进程内已缓存 `AuthSession`）
- **并且** 前端通过 `auth client` 调用“获取当前会话”能力（例如读取 `/auth/me`）
- **那么** 系统必须返回与登录成功时结构一致的 `AuthSession` 对象
- **并且** 认证上下文 Hook（如 `useAuthContext`）必须能够在组件中读取到当前用户与组织信息

#### 场景：未登录查询当前会话

- **当** 当前进程内不存在任何已登录会话
- **并且** 前端通过 `auth client` 调用“获取当前会话”能力
- **那么** `/auth/me` 必须返回 `null`
- **并且** 认证上下文 Hook 必须向下游组件暴露 `user === null`、`organization === undefined`
- **并且** 依赖认证信息的 UI 组件（例如顶部导航中的用户头像/组织切换）应根据无会话状态采取降级展示（例如提示需要登录或隐藏受保护信息）

#### 场景：登出后会话被清空

- **当** 用户在已登录状态下触发登出操作（例如点击“退出登录”按钮）
- **那么** 前端必须调用 `/auth/logout` 接口
- **并且** MSW 必须拦截登出请求并清空当前进程内维护的会话状态
- **并且** 后续对 `/auth/me` 的调用必须返回 `null`
- **并且** 认证上下文 Hook 必须将 `user` 重置为 `null`，`organization` 置为 `undefined`
- **并且** 受保护路由或导航项在下次渲染时必须视用户为未登录状态（例如跳转回登录页或显示登录入口）
